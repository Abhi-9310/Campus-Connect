# Campus Connect deployment

## Architecture

- Vercel: React + Vite frontend.
- Render: Express API and persistent Socket.IO server.
- MongoDB Atlas: users, connections, messages and notifications.
- Cloudinary: profile images.

## Backend setup on Render

Create a Web Service from this repository and select branch `deployment/render-mongodb`.

- Runtime: Node
- Build command: `npm install`
- Start command: `npm start`
- Health check path: `/api/health`

Set these environment variables in Render:

- `NODE_ENV=production`
- `MONGODB_URI`: MongoDB Atlas driver connection string.
- `JWT_SECRET`: a long random secret generated by Render or a password manager.
- `CLIENT_URL`: the exact Vercel frontend origin, e.g. `https://campusconnect-omega-nine.vercel.app`.
- `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`: Cloudinary credentials.

Render supplies `PORT` automatically. Do not hard-code it.

## Frontend setup on Vercel

Keep the existing Vercel project and set:

- `VITE_API_URL`: the Render service origin, e.g. `https://campus-connect-api.onrender.com`, without a trailing slash.

Redeploy the Vercel frontend after adding or changing this variable.

## MongoDB Atlas

1. Create a free cluster and a dedicated database user.
2. Add the network access rule required by Render. For a simple initial setup, Atlas may be configured to allow connections from `0.0.0.0/0`; use a strong database password and a least-privilege user.
3. Copy the Node.js driver connection string and set it as `MONGODB_URI` in Render.
4. Never commit the URI, database password, or JWT secret to GitHub.

The backend creates indexes and loads its application collections when it starts. The MongoDB database is the persistent source of truth; the in-memory arrays are process caches.

## Verify after deployment

1. Open `https://YOUR-RENDER-SERVICE.onrender.com/api/health`; expect JSON with `status: "ok"`.
2. Test registration with a new account, then log in.
3. Test profile edits, avatar upload/removal, connection requests, notifications and messages.
4. Open two authenticated browser sessions and test real-time Socket.IO delivery.

## Notes

- Existing JSON files are no longer used for application persistence.
- Profile images are uploaded to Cloudinary rather than the Render filesystem.
- Render free instances may sleep when idle, so the first request after inactivity can be slow.
- This migration branch is separate from `main`; review and merge it only after the deployment tests pass.
